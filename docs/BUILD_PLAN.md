## Product summary

A free, open-source, mobile-first web app for tracking progressive overload at the gym. Users add it to their phone home screen (PWA). Anyone can self-host it on Vercel + MongoDB Atlas.

The user has a split of N workout days (e.g. "Chest + Back", "Legs", …). At the gym they tap the day they are doing, and a page opens listing that day's exercises. For each exercise they log sets (weight × reps) live, set by set. Next to each exercise they see **what they did last time**, so they know what to beat. Progress pages show charts and an overall strength score.

## Product decisions (fixed — do not change)

| Topic | Decision |
|---|---|
| Accounts | Username + password only. No email, no password reset, no OAuth. |
| Number of days | User-defined. **New users start with 4 days** named "Day 1" … "Day 4", all empty. Users can add (max 14), rename, reorder and delete days (min 1). |
| Day order | Days are a **rotation**, not tied to weekdays. "Up next" = the day after the day of the most recently finished workout (wrapping around). |
| Exercise library | **There is no seeded/global library. Zero exercises exist by default.** Each user creates their own exercises (by typing a name). Users never see other users' exercises. |
| Recommendations | **The app never recommends weights, reps or targets.** It only shows what the user did last time and a small ▲ / ▼ / = comparison per set. No rep ranges, no "increase weight" prompts. |
| Logging | Live, at the gym, set by set. Every change auto-saves to the server. |
| Units | Per-user setting, `kg` (default) or `lb`. **All weights are stored in kg** in the database and converted for display/input. |
| Bodyweight exercises | No special handling. Users can type 0 as weight. Sets with weight 0 are stored but ignored by stats/charts. |
| Offline | Not supported in v1. Online only. |
| Strength score | Defined in Task 11. 100 = where you started. |
| Charts | Strength score over time + per-exercise estimated 1RM over time. |

## Tech decisions (fixed — do not change)

- **Next.js 15** (App Router, TypeScript, `src/` dir, `@/*` alias), **Tailwind CSS v4** (as generated by create-next-app 15), ESLint.
- **MongoDB Atlas** via **mongoose@^8**.
- Passwords: **bcryptjs** (pure JS, cost 10). Sessions: **jose** HS256 JWT in an httpOnly cookie named `po_session`, valid 30 days.
- Charts: **recharts@^3**.
- Tests for pure logic: **vitest**.
- **No other runtime dependencies.** Specifically: no next-auth, no zod, no UI component kits, no state libraries, no date libraries, no SWR/React Query.
- Pages are **client components** (`"use client"`) that call our own JSON API routes with `fetch`. API routes are the only code that touches the database.
- Next.js 15 specifics to remember:
  - `cookies()` from `next/headers` is **async**: `const store = await cookies()`.
  - Dynamic route handler params are a **Promise**: `{ params }: { params: Promise<{ id: string }> }` → `const { id } = await params`.
  - In client pages, read route params with `useParams()` from `next/navigation`.

## Data model

All documents belong to a user via `userId`. **Every query in every API route must filter by the logged-in user's `userId`.** A user must never be able to read or modify another user's data, even by guessing IDs.

### User
| Field | Type | Notes |
|---|---|---|
| `username` | string, required, unique | Stored lowercase, trimmed. 3–24 chars, `^[a-z0-9_]+$` |
| `passwordHash` | string, required | bcrypt hash |
| `unit` | `'kg' \| 'lb'`, default `'kg'` | |
| `createdAt` | Date | via `timestamps: true` |

### Exercise
| Field | Type | Notes |
|---|---|---|
| `userId` | ObjectId, required, indexed | |
| `name` | string, required | Trimmed, 1–60 chars, display casing kept |
| `nameLower` | string, required | `name.toLowerCase()`, used for duplicate checks |
| `archived` | boolean, default `false` | "Deleting" an exercise archives it so history is kept |

Index: `{ userId: 1, nameLower: 1 }` unique.

### WorkoutDay
| Field | Type | Notes |
|---|---|---|
| `userId` | ObjectId, required, indexed | |
| `name` | string, required | Trimmed, 1–40 chars |
| `order` | number, required | 0-based position in the rotation |
| `exerciseIds` | ObjectId[] | Ordered list of Exercise ids |

### Session (one gym visit)
| Field | Type | Notes |
|---|---|---|
| `userId` | ObjectId, required, indexed | |
| `dayId` | ObjectId, required | The WorkoutDay that was trained |
| `dayName` | string, required | Snapshot of the day name at start (survives rename/delete) |
| `startedAt` | Date, required | |
| `finishedAt` | Date or `null`, default `null` | `null` = workout in progress |
| `entries` | `{ exerciseId: ObjectId, sets: { weight: number, reps: number }[] }[]` | `weight` in **kg**, `reps` integer |

Index: `{ userId: 1, startedAt: -1 }`.

A user has **at most one** session with `finishedAt: null` at a time (enforced in code, Task 8).

## API conventions

- All routes live under `src/app/api/**/route.ts` and return JSON.
- Success: the documented JSON body with status 200 (or 201 for creation).
- Error: `{ "error": "Human readable message" }` with status 400 (bad input), 401 (not logged in), 404 (not found **or not owned by this user**), 409 (conflict).
- Always return ids as `id: string`, never `_id`. Use `.lean()` and map documents to plain objects.
- Validate every id param with `mongoose.isValidObjectId(id)`; invalid → 404.
- Every route except register/login/logout starts with:

```ts
const userId = await getUserId();
if (!userId) return jsonError('Unauthorized', 401);
await dbConnect();
```

## Task 1: Database connection + models

**Files:** `src/lib/db.ts`, `src/models/User.ts`, `src/models/Exercise.ts`, `src/models/WorkoutDay.ts`, `src/models/Session.ts`

1. `src/lib/db.ts`:
   ```ts
   import mongoose from 'mongoose';

   type Cache = { conn: typeof mongoose | null; promise: Promise<typeof mongoose> | null };
   const g = globalThis as unknown as { _mongoose?: Cache };
   const cache: Cache = g._mongoose ?? (g._mongoose = { conn: null, promise: null });

   export async function dbConnect() {
     if (cache.conn) return cache.conn;
     const uri = process.env.MONGODB_URI;
     if (!uri) throw new Error('MONGODB_URI is not set');
     cache.promise ??= mongoose.connect(uri, {
       dbName: process.env.MONGODB_DB || 'progressive-overload',
       bufferCommands: false,
     });
     try {
       cache.conn = await cache.promise;
     } catch (e) {
       cache.promise = null;
       throw e;
     }
     return cache.conn;
   }
   ```
2. One file per model, following the Data model section exactly. Use this pattern so hot reload doesn't throw `OverwriteModelError`:
   ```ts
   import { Schema, model, models, type Model, type InferSchemaType } from 'mongoose';

   const userSchema = new Schema(
     {
       username: { type: String, required: true, unique: true, lowercase: true, trim: true },
       passwordHash: { type: String, required: true },
   ```

## Task 2: Auth library + middleware

**Files:** `src/lib/jwt.ts`, `src/lib/auth.ts`, `src/lib/http.ts`, `src/middleware.ts`

1. `src/lib/jwt.ts` (edge-safe: imports **only** `jose`, because middleware runs on the edge runtime):
   ```ts
   import { SignJWT, jwtVerify } from 'jose';

   export const SESSION_COOKIE = 'po_session';
   export const SESSION_MAX_AGE = 60 * 60 * 24 * 30; // 30 days, in seconds

   function key() {
     const secret = process.env.AUTH_SECRET;
     if (!secret) throw new Error('AUTH_SECRET is not set');
     return new TextEncoder().encode(secret);
   }

   export async function signSession(userId: string) {
     return new SignJWT({})
       .setProtectedHeader({ alg: 'HS256' })
       .setSubject(userId)
       .setIssuedAt()
       .setExpirationTime(`${SESSION_MAX_AGE}s`)
       .sign(key());
   }

   export async function verifySession(token: string | undefined): Promise<string | null> {
     if (!token) return null;
     try {
       const { payload } = await jwtVerify(token, key());
       return payload.sub ?? null;
     } catch {
       return null;
     }
   }
   ```
2. `src/lib/auth.ts` (server only):
   ```ts
   import bcrypt from 'bcryptjs';
   import { cookies } from 'next/headers';
   import { SESSION_COOKIE, SESSION_MAX_AGE, signSession, verifySession } from './jwt';

   export const hashPassword = (pw: string) => bcrypt.hash(pw, 10);
   export const checkPassword = (pw: string, hash: string) => bcrypt.compare(pw, hash);

   export async function getUserId() {
     const store = await cookies();
     return verifySession(store.get(SESSION_COOKIE)?.value);
   }

   export async function setSessionCookie(userId: string) {
     const store = await cookies();
     store.set(SESSION_COOKIE, await signSession(userId), {
       httpOnly: true,
       secure: process.env.NODE_ENV === 'production',
       sameSite: 'lax',
       path: '/',
       maxAge: SESSION_MAX_AGE,
     });
   }

   export async function clearSessionCookie() {
     const store = await cookies();
     store.delete(SESSION_COOKIE);
   }
   ```
3. `src/lib/http.ts`:
   ```ts
   import { NextResponse } from 'next/server';

   export const json = (data: unknown, status = 200) => NextResponse.json(data, { status });
   export const jsonError = (error: string, status: number) => NextResponse.json({ error }, { status });

   export async function readJson(req: Request): Promise<Record<string, unknown> | null> {
     try {
       const body = await req.json();
       return body && typeof body === 'object' && !Array.isArray(body) ? body : null;
     } catch {
       return null;
     }
   }
   ```
4. `src/middleware.ts`:
   ```ts
   import { NextResponse, type NextRequest } from 'next/server';
   import { SESSION_COOKIE, verifySession } from '@/lib/jwt';

   const PUBLIC_PAGES = ['/login', '/register'];

   export async function middleware(req: NextRequest) {
     const { pathname } = req.nextUrl;
     const userId = await verifySession(req.cookies.get(SESSION_COOKIE)?.value);
     const isPublic = PUBLIC_PAGES.includes(pathname);
     if (!userId && !isPublic) return NextResponse.redirect(new URL('/login', req.url));
     if (userId && isPublic) return NextResponse.redirect(new URL('/', req.url));
     return NextResponse.next();
   }

   export const config = {
     // API routes do their own 401 handling; static assets, icons and the manifest must stay public.
     matcher: ['/((?!api|_next/static|_next/image|favicon.ico|icon|apple-icon|icons|manifest.webmanifest).*)'],
   };
   ```

   ```ts
   export async function api<T>(path: string, options: { method?: string; body?: unknown } = {}): Promise<T> {
     const res = await fetch(path, {
       method: options.method ?? 'GET',
       headers: options.body !== undefined ? { 'Content-Type': 'application/json' } : undefined,
       body: options.body !== undefined ? JSON.stringify(options.body) : undefined,
   ```

## Task 11: Stats library + stats API

**Files:** `src/lib/stats.ts`, `src/lib/stats.test.ts`, `src/app/api/stats/route.ts`

### Definitions
- **Estimated 1RM (Epley):** `e1rm(weightKg, reps) = weightKg * (1 + reps / 30)`. Returns 0 if `weightKg <= 0` or `reps <= 0`.
- **Session best** for an exercise: the max `e1rm` over that exercise's sets in that session.
- **Strength score** at a point in time:
  1. Consider every finished session up to and including that point, oldest first.
  2. For each exercise with at least one session best > 0: `first` = its session best in the **first** session where it had one, `latest` = its session best in the **most recent** session where it had one.
  3. `score = 100 × average over those exercises of (latest / first)`, rounded to 1 decimal.
  4. 100 = where you started. 112.5 = on average 12.5% stronger than your first logged sessions. Exercises are weighted equally regardless of how heavy they are. The score can go down.

### `src/lib/stats.ts`
```ts
export type SetLog = { weight: number; reps: number }; // weight in kg
export type SessionLog = { date: string; entries: { exerciseId: string; sets: SetLog[] }[] };

export function e1rm(weightKg: number, reps: number): number;
export function bestE1rm(sets: SetLog[]): number; // 0 if none valid

/** sessions in any order; returns one point per session that has any valid data, oldest first */
export function strengthSeries(sessions: SessionLog[]): { date: string; score: number }[];

/** per exercise: one point per session where it had a valid best, oldest first */
export function exerciseSeries(
  sessions: SessionLog[],
): Record<string, { date: string; e1rm: number; best: SetLog }[]>; // best = the set that produced the max e1rm
```

Tests (`stats.test.ts`), at least:
- `e1rm(100, 10)` ≈ 133.33; `e1rm(0, 10) === 0`; `e1rm(100, 0) === 0`.
- `bestE1rm` picks the max and ignores zero-weight sets.
- `strengthSeries`: one session → `[{score: 100}]`; two sessions where exercise A goes 100→110 e1RM and B stays the same → second score is 105; sessions passed out of order are sorted; a session with only zero-weight sets produces no point; an exercise that first appears in a later session contributes 1.0 (100%) in that session.
- `exerciseSeries` returns the right `best` set.

### GET `/api/stats`
- Load all the user's **finished** sessions (`select('startedAt entries')`, lean), map to `SessionLog` (`date` = `startedAt` ISO, ids as strings).
- Load the user's exercises (including archived) for names.
- Response:
  ```ts
  {
    score: number | null,                       // last point of strengthSeries, or null
    scoreSeries: { date: string; score: number }[],
    exercises: { id: string; name: string; archived: boolean; series: { date: string; e1rm: number; best: { weight: number; reps: number } }[] }[],
  }
  ```
  `exercises` includes only exercises with at least one point, sorted by name. All weights are in kg.
